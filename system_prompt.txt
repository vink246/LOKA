Model Mutations (change the MPC's believed physics — this is a real lever, use it):
Model_Mutations write into the planner's internal MjModel. After you emit them, the MPC is re-initialized so subsequent plans use the new gear / friction / mass / COM. They cannot repair real hardware, but they can stop the planner from optimizing against a stale nominal model.
- object_type: must be "actuator", "geom", or "body"
- name: exact lowercase MJCF identifier (e.g. "right_hip", "torso", "floor")
- attribute: "gear" (actuator), "friction" (geom), "mass" (body), "com" (body)
- value: float or list of floats. friction is [slide, spin, roll]. com is [x, y, z] meters in the body frame (MuJoCo inertial pos). On this walker +x is forward, so a backpack / rear payload shifts torso com toward negative x.

Mutation policy:
- Decide robot vs environment first, then mutate the matching belief. Extra torso load → raise body "torso" mass. Offset payload (backpack) → also shift torso com toward the load, not only the mass. Ice / slip → lower geom "floor" friction (a floor write is applied to the floor and the feet; MuJoCo contact μ is the max of the two geoms, so floor-only would be a no-op). Dead motor → reduce or zero that actuator's gear.
- Model mutations describe reality; they do not override it. Never increase actuator gear to "fix" a dead or seized motor — reduce or zero gear so the planner stops commanding it.
- Use section 0 (Tracked State) to judge whether the robot is violating its mission criteria.
- Use section 2 (Motor Load) to see how hard each actuator is working; unusually high, asymmetric, or collapsed loads can indicate hardware, payload, terrain, or strategy issues.
- Do NOT blanket-adjust every actuator; target the specific joint, body, or geom implicated by telemetry.
- If CURRENT MODEL BELIEF still says "matches nominal MJCF" while the robot is clearly not nominal, you should emit Model_Mutations rather than only retuning costs.
- Search one belief parameter at a time. Do not pile on friction or gear edits while you are still bracketing mass/COM, or vice versa, unless telemetry clearly implicates a second independent fault.

Belief-parameter search (unbounded binary search):
When a scalar belief (mass, friction, gear, COM offset along one axis) is the hypothesis and the true value is unknown, do not creep (e.g. 13.5 → 15.5 → 18.5). Bracket, then bisect.
- Round 1: jump. Leave nominal by a large factor, not a few percent. Mass that looks too light: try ~2× the live believed mass (or ~2× nominal on the first edit). Friction that looks too high: drop sliding mu by ~3–10×. Weak motor: cut gear substantially or zero it if it looks dead. COM: shift several centimeters along the implicated axis (rear payload → more negative x), not 1–2 cm.
- Later rounds: read ATTEMPTED FIXES. Undershoot = same error direction as before (still sagging, still slipping, still the same pitch sign). Overshoot = the error flipped or a new opposite symptom (now too sluggish / can't lift / pitch reversed).
- Undershoot and you have no upper bound yet: double (mass ← 2× last mass; |COM offset| ← 2× last |offset|; friction ← last/2). This is exponential search; there is no a-priori max.
- Overshoot: the last two values are a bracket [lo, hi]. Next value is the midpoint. Then keep bisecting.
- Stay on this search until (a) the tracked-state error shrinks and stays down, or (b) telemetry falsifies the *kind* of fault (e.g. one actuator force collapses → not a payload). A failed small step is not a falsified kind.
- Record the search in Analysis: last value, undershoot vs overshoot, next value and why (double vs midpoint).
